The business case, in one line

Closing the Data Access and Integration gaps unlocks every upstream element — Service, Process, Outcome — because those weak scores are caused by the missing plumbing. A rand spent on integration returns maturity across eight elements at once. That is the argument the future-state target is built to make.

Target set deliberately at 3.0 ("documented, measured, managed") — not 5. A realistic first-cycle destination beats an aspirational one that never gets funded.

Transition roadmap

The gap is sequenced into three transition architectures. Each horizon is a coherent, fundable state — not a big-bang.

H1Stabilise & enable · 0–12 months
  • Stand up the change-and-delivery capability (clears the hard gate — see below)
  • Appoint a data steward; start the beneficiary golden record
  • Replace hand-keying and flash-drives with a secured, logged file exchange (POPIA)
  • Pilot one governed API for beneficiary look-up
H2Integrate · 12–24 months
  • MIOS-conformant integration layer / API gateway (PSR Reg 97)
  • Departmental applications migrated onto transversal, governed platforms
  • Beneficiary golden record consumed via API by provinces and metros
  • Online subsidy application with status tracking (digital self-service)
H3Transform to DPI · 24–48 months
  • Federated national interoperability (MzansiXhange / DPI) for tenure and title
  • End-to-end citizen services pre-filled from national DPI
  • Real-time verification of title deeds and subsidy eligibility
Hard gate governs the roadmap. The enabling-environment assessment finds no standing change-and-delivery capability. Until Horizon-1 builds it, no ambitious architecture change may be scheduled. Describing a future state you have no capacity to reach is, in GWEA's words, "an exercise in futility." See the Enabling Environment →
